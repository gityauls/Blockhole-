# 알툴즈 Web 분석 브리프

- 대상: https://web.altools.com/ko
- 분석일: 2026-11-07
- 방법: Chrome 자동화로 데스크톱·모바일 화면 측정, 직접 만든 작은 PNG·PDF로 도구 실행, 공개된 `/license.txt` 확인
- 캡처: `screenshots/` (로컬 전용, git 제외)

## 핵심 결론

1. **대부분의 변환은 서버 없이 브라우저에서 처리한다.** WASM(pdfium, 7-Zip 등)을 쓰기 때문에 파일을 올리지 않고, 드롭한 뒤 필요한 엔진만 내려받는다.
2. **서버가 필요한 기능은 일부다.** Office·HWP를 PDF로 바꾸기, PDF 압축, AI 기능이 서버 처리다.
3. **화면 구조는 단순한 반복이다.** 홈은 카드 그리드, 모든 도구는 같은 3단계 틀(드롭 → 옵션 → 결과)을 쓴다. 공통 틀 하나로 도구를 늘릴 수 있다.
4. **기술 스택이 우리 템플릿과 거의 같다.** Next.js, Tailwind, Radix/shadcn 계열, lucide-react, Pretendard를 쓴다.

## 도구별 처리 위치와 제한

처리 위치는 사이트의 안내 문구 기준이다. ✔ 표시는 네트워크 기록으로 직접 확인한 항목이다.

| 분류 | 도구 | 처리 위치 | 입력 / 최대 크기 |
|---|---|---|---|
| 이미지 | 이미지 변환 ✔ | 브라우저 | BMP, JPG, PNG, WEBP / 100MB |
| 이미지 | 이미지 편집 | 브라우저 | 같은 형식 / 30MB |
| PDF 변환 | PDF → Word ✔, Excel, PPT, JPG, TXT | 브라우저 | PDF / 500MB |
| PDF 변환 | 이미지 → PDF | 브라우저 | JPG, PNG, BMP, WEBP / 30MB |
| PDF 변환 | Word, Excel, PPT → PDF | 서버 | Office 문서 / 300MB |
| PDF 변환 | HWP → PDF | 서버 | HWP, HWPX / 300MB |
| PDF 변환 | TXT → PDF | 서버 | TXT / 3MB |
| PDF 편집 | 병합, 분할, 구성 | 브라우저 | PDF / 500MB |
| PDF 편집 | PDF 압축 ✔ | 서버 (`POST /api/tool/pdf-compress`) | PDF / 200MB |
| 압축 | ALZ, EGG, RAR, 7z → ZIP | 브라우저 | 각 형식 / 1024MB |
| AI | 화질 개선, 배경 제거, 지우개 | 서버 | 이미지 / 10MB |
| 문서 | Markdown으로 변환 | 서버 | 안내 문구 기준, 크기 미확인 |

AI 얼굴 모자이크는 페이지 HTML에서 처리 위치와 제한을 확인하지 못했다.

## 사용 라이브러리 (`/license.txt` 공개 목록)

| 용도 | 라이브러리 |
|---|---|
| PDF 렌더링·추출 | @embedpdf/pdfium, pdf.js |
| PDF 생성·편집 | pdf-lib, qpdf, pdfcpu |
| Office 파일 생성 | docx, exceljs, pptxgenjs |
| Office → PDF (서버 추정) | LibreOffice |
| 압축 파일 | 7z-wasm, fflate, jszip |
| 이미지 | sharp(서버), resvg, libheif, heic-convert |
| HWP | rhwp |
| Markdown | markitdown, anydoc, marked |
| AI 모델 | Real-ESRGAN, GFPGAN, LaMa, BiRefNet, FaceXLib |
| UI | Radix UI, lucide-react, dnd kit, embla-carousel, sonner, next-intl, lottie-react |

어떤 라이브러리가 어떤 도구에 쓰이는지는 목록에 나오지 않으므로, 위 분류는 용도 기준의 추정이다.

**라이선스 주의:** 7-Zip은 LGPL에 unRAR 제한이 붙고, libvips와 libheif는 LGPL이다. 공개 전에 고지 의무와 RAR 해제 조건을 확인해야 한다.

## 화면 구조

### 공통 헤더
- 높이 약 60px. 왼쪽 로고, 가운데 메뉴, 오른쪽 블로그·의견 보내기·언어 선택.
- 메뉴 항목을 클릭하면 도구 목록 드롭다운이 열린다. PDF 도구는 3열 구성이다.
- 390px에서는 로고와 햄버거 메뉴만 남는다.

### 홈
순서: 히어로 → 카테고리 필터 → 도구 카드 그리드 → 카테고리별 소개 6개 → FAQ → 푸터

| 항목 | 값 |
|---|---|
| 콘텐츠 폭 | 1100px (1440px 화면에서 좌우 170px) |
| 그리드 | 4열 260px (1024px 이상), 3열 (768px), 2열 (390px) |
| 카드 | 이미지 4:3 상단 + 제목 + 설명, 카드 간격 20px |
| 카테고리 필터 | 알약형 버튼, 활성은 검정 배경 |
| 필터 동작 | URL 변화 없이 카드만 교체 (PDF 선택 시 16개) |
| 스크롤 | 문서 전체가 아니라 내부 영역이 스크롤됨 |

### 도구 페이지

| 상태 | 화면 |
|---|---|
| 대기 | 가운데 제목과 설명, 왼쪽 일러스트, 오른쪽 드롭 영역, 아래 관련 도구 슬라이더와 FAQ |
| 드래그 중 | 드롭 영역 테두리와 배경이 파란색으로 변함 |
| 파일 선택 | 파일 목록(이름, 크기, 형식)과 파일 추가 칸, 옵션과 실행 버튼 |
| 결과 | 저장, 새 작업, 의견 보내기, "이 파일로 계속하기" |

두 가지 흐름이 있다.
- **옵션이 있는 도구** (이미지 변환, PDF 압축): 드롭 → 옵션 선택 → 실행 버튼 → 저장
- **옵션이 없는 도구** (PDF → Word): 드롭 즉시 자동 변환 → 저장

"이 파일로 계속하기"는 결과 파일을 다음 도구로 바로 넘기는 기능이다. 예를 들어 PDF 압축 결과에서 편집, 병합, 분할, 변환으로 이어진다.

## 1단계 구현 제안

서버 없이 동작하는 기능부터 만든다. 3단계의 수익 모델 결정 전에 서버 비용이 들지 않는다.

| 순서 | 범위 | 라이브러리 |
|---|---|---|
| 1 | 공통 틀: 헤더, 홈, 드롭 영역, 3단계 도구 페이지 | shadcn/ui, Radix |
| 2 | 이미지 변환 (JPG, PNG, WEBP) | 브라우저 Canvas |
| 3 | PDF 병합·분할, 이미지 → PDF, PDF → JPG·TXT | pdf-lib, pdf.js |
| 4 | PDF → Word·Excel·PPT | pdfium, docx, exceljs, pptxgenjs |
| 5 | 압축 변환 → ZIP | 7z-wasm, fflate |

## 확인하지 못한 것
- PDF 압축 옵션의 전체 목록 (기본값 "보통"만 확인)
- 큰 파일을 넣었을 때의 진행 표시와 오류 화면
- 병합의 실제 실행 (파일 1개로는 실행하지 않음), 카드 호버 외 세부 애니메이션
- 카드 반경 등 일부 값은 측정 출력이 잘려 화면 기준으로만 확인
- 도구 페이지의 모바일 화면
