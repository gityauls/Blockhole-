# 변환 완성도 로드맵

작성: 2026-11-07. 이 문서는 File-BlackHole의 핵심 과제와 그 해결 과정을 기록한다. 작업을 시작할 때마다 이 문서를 먼저 읽고, 끝날 때 문제 기록을 갱신한다.

## 핵심 문제

지금의 PDF → Word·Excel·PowerPoint 변환은 **단순 변환 수준의 초안**이다. 글자는 거의 정확하게 뽑히지만, 결과 파일을 열면 원본 구조가 살아 있지 않아서 다시 손봐야 한다.

- 결과물을 바로 쓸 수 없으면 사람들은 돈을 내지 않는다.
- 다른 변환 사이트와 같은 수준이면 차별점이 없다.

## 목표

**변환한 파일을 Word·Excel·PowerPoint에서 열었을 때 손보지 않고 바로 쓸 수 있게 만든다.** 표는 표로, 병합 셀은 병합 셀로, 그림은 제자리에, 서식과 읽는 순서는 원본대로 나와야 한다.

새 형식 추가(압축 파일 → ZIP 등)는 이 목표를 이룰 때까지 미룬다.

## 원칙

1. **타협하지 않는다.** 증상만 가리는 땜질 대신 근본 원인을 찾아 해결한다.
2. **샘플은 감을 잡는 도구다.** 샘플 개수가 목표가 아니다. 원인이 보이지 않으면 샘플을 늘리고 조건을 바꿔 다시 본다.
3. **순환한다.** 아래 순서를 문제가 풀릴 때까지 반복한다.

   ```
   원인 분석 → 연구 → 파악 → 해결 → 검증
       ↑                              │
       └──────── 안 풀리면 ───────────┘
   ```

4. **막히면 단계를 올린다.**

   | 단계 | 방법 | 언제 |
   |---|---|---|
   | 1 | 연구: PDF 구조, 라이브러리 기능, 공개 자료로 해결 | 기본 |
   | 2 | Office 역분석: Office가 직접 저장한 파일(OOXML)을 풀어 구조를 비교하고 그대로 재현 | 1단계로 안 풀릴 때 |
   | 3 | Office로 실제 제작한 틀(템플릿)과 기본 구현을 합쳐 원하는 결과에 맞춤 | 2단계로도 안 풀릴 때 |

5. **정답지는 진짜 Office가 만든다.** 샘플은 Word·Excel·PowerPoint로 직접 만들고, 같은 프로그램의 "PDF로 저장"으로 PDF를 만든다. 원본 Office 파일이 정답이고, 우리 변환 결과를 여기에 비교한다.

## 검증 방법

같은 조건에서 매번 다음을 비교한다.

| 구분 | 비교 항목 |
|---|---|
| 구조 (숫자) | 표 개수, 행·열·셀 수, 병합 범위, 글자 일치율, 그림 수와 위치, 쪽·시트·슬라이드 수, 글꼴·크기·굵기·색, 파일 용량 |
| 화면 (눈) | 원본과 변환본의 같은 쪽을 PNG로 내보내 나란히 비교 |
| 열림 | Office 16에서 경고나 복구 안내 없이 열리는지 (`DisplayAlerts`를 끄지 않고 확인) |
| 실사용 | 표에 행 추가, 엑셀 합계 수식, 슬라이드 글자 수정 같은 실제 작업이 되는지 |

## 첫 샘플 세트

시작점일 뿐이며, 원인 파악에 필요하면 계속 추가한다.

| 형식 | 샘플 | 보려는 것 |
|---|---|---|
| Word | 단순 격자 표 (머리글 + 숫자) | 표가 표로 복원되는가 |
| Word | 가로·세로 병합 셀, 여러 줄 셀 | 병합과 셀 안 줄바꿈 |
| Word | 여러 쪽에 걸친 긴 표, 표 앞뒤 본문과 그림 | 머리글 반복, 쪽 넘김, 그림 위치 |
| Excel | 가로 병합 제목 | 병합 복원 |
| Excel | 세로 병합 분류 열 | 병합하면 왼쪽 위 값만 남는 규칙을 지키는가 |
| Excel | 숫자·날짜·통화 서식, 줄바꿈 셀, 테두리 | 값의 형식과 서식 |
| PowerPoint | 글자 위주 슬라이드 20장 | 용량, 글상자 위치 |
| PowerPoint | 사진 위주 슬라이드 | 용량, 그림 품질 |
| PowerPoint | 도형·차트·글상자 혼합 | 편집 가능 여부, 겹침 |
| 실제 문서 | 농업재해보험 이론서 (347쪽, 두 쪽 펼침) | 실제 문서에서의 종합 품질 |

## 현재 상태 (초안, 커밋 `c7d1d44`)

방식: 브라우저 안에서만 처리한다. pdf.js로 글자 위치를 읽고 docx, pptxgenjs, 자체 XLSX 작성기로 파일을 만든다.

이론서 347쪽 결과:

| 형식 | 시간 | 용량 | 열림 |
|---|---|---|---|
| Word | 약 7초 | 0.4MB | 614쪽, 한글 315,848자 일치 |
| Excel | 약 6초 | 0.7MB | 시트 346개 |
| PowerPoint | 약 36초 | 30MB (원본 4.4MB) | 슬라이드 347장 |

### 해결 방향 (근본)

글자만 보는 지금 방식을 고치는 대신, **표를 먼저 찾고 글을 칸에 넣는** 순서로 바꾼다.

1. 표 찾기: 그리기 명령에서 가로·세로 선(선 긋기와 얇은 채움 사각형 모두)을 모아 격자를 만든다.
2. 칸 나누기: 격자의 교차점으로 칸을 정하고, 선이 끊긴 곳을 병합 셀(가로 gridSpan, 세로 vMerge)로 본다.
3. 글 넣기: 글자 조각을 위치로 칸에 넣는다. 칸 안에서 줄바뀜한 글은 한 셀의 여러 줄로 합친다. 문제 12, 13이 함께 풀린다.
4. 표 영역은 단 나눔 계산에서 뺀다. 문제 11이 풀린다.
5. 태그 PDF는 구조 트리로 결과를 확인하거나 보강한다. 선이 없는 표는 그 다음 단계(글자 정렬 기반)로 다룬다.
6. 검증: 같은 샘플로 셀 일치율을 다시 재고, 이론서 표 쪽을 눈으로 비교한다.
