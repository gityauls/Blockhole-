## 1단계: 알툴즈 분석 및 구현
- 참조: https://web.altools.com/ko
- 분석 결과: [research/altools/brief.md](research/altools/brief.md)
- 완료 기준: 파일을 드롭해 원하는 형식으로 변환하고 내려받을 수 있다. `npm run check`가 통과한다.
- 브랜드: 자체 브랜드 File-BlackHole. 알툴즈는 구조와 작동 방식만 참고한다.
- 구현 현황:
  - [x] 공통 틀, 창 전체 드롭, 포털 브랜드 화면
  - [x] 이미지 변환 (JPG, PNG, WEBP, BMP, ZIP 일괄 저장)
  - [x] PDF 병합·분할, 이미지 → PDF, PDF → JPG·TXT
  - [x] PDF → Word·Excel·PPT (글자 중심, 알려진 한계는 PROJECT.md)
  - [ ] 압축 파일 → ZIP (보류: 아래 완성도 목표를 먼저 진행)

### 다음 목표: 변환 완성도 (2026-11-07 결정)
- 새 형식을 늘리기 전에, 이미 만든 변환의 결과물을 원본에 가깝게 재현한다.
- 이유: 남들과 같은 수준으로는 차별점이 없고, 유료화하려면 결과물을 바로 쓸 수 있어야 한다.
- 방법: Word·Excel·PowerPoint에서 직접 만든 결과물과 우리 변환 결과를 비교·분석해, 열었을 때 원본 구조(표, 그림, 단, 서식)가 살아 있게 만든다.
- 우선 과제: PROJECT.md의 알려진 한계 (표 복원, 글자 페이지의 그림, 표 선·병합 셀, 3단 이상, PPT 크기)

## 2단계: 유료 사이트 기술 및 추가 기능
- 참조: https://www.freeconvert.com/ko , https://convertio.co/kr/
- 확인할 것: 지원 형식, 파일 크기 제한, 서버 처리 구조, 대용량 처리 방식, 요금 체계
- 완료 기준: 도입할 기능을 정하고 구현한다.

## 3단계: 수익 모델 결정
- 유료화: 서버 비용, 결제 연동, 사업자 요건, 약관과 개인정보 처리
- 무료+광고: 광고 플랫폼 승인 조건, 예상 트래픽과 수익
- 완료 기준: 비용과 수익을 비교해 하나를 결정하고 이유를 기록한다.

## 4단계: 완성 및 배포
- 공개 전 점검: [PROJECT.md의 공개 전 원칙](PROJECT.md#공개-전-원칙)
- 사이트에 오픈소스 라이선스 고지 페이지 추가 (pdf-lib, pdf.js, fflate, 폰트 등)
- 호스팅은 무료 범위에서 Vercel과 Supabase 계정을 활용한다. 연결 전에 사용자에게 먼저 알린다.
- 완료 기준: 실제 주소로 접속해 변환이 동작한다.
